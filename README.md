# Детекция подделки речи

## Итоговое решение

Финальная модель — `lcnn64_lfcc_mean_bce`, публичный тест **97.65**.

| | |
| --- | --- |
| Признаки | LFCC, 40 коэффициентов, `n_fft=1024`, `hop=512`, 128 линейных фильтров, z-норма на запись; аудио 16 кГц, 6 с (обрезка или дополнение нулями) |
| Сеть | LCNN: 4 блока Conv3×3 → BatchNorm → Max-Feature-Map → MaxPool, ширина 64, global average pooling, dropout 0.42, один логит |
| Обучение | BCE с `pos_weight`, AdamW `lr=2.09e-3`, `weight_decay=5.3e-4`, батч 32, 10 эпох без early stopping, AMP; все 25 380 размеченных записей |
| Семена | 0, 1, 2 — по CSV на семя |
| LOSO (6 фолдов A01–A06, 3 семени) | средний AUC 0.989, худший фолд 0.949 (A06) |

Гиперпараметры записаны в `outputs/stage2/metrics.json` (`best_params`). Веса: `outputs/stage2/final_checkpoints/seed_{0,1,2}.pt`. Файлы сдачи: `outputs/submission_seed_0.csv`, `outputs/submission_seed_1.csv`, `outputs/submission_seed_2.csv`, колонки `idx`, `score` (вероятность подделки).

Модель выбрал leave-one-synthesizer-out, не публичный тест. Новая гипотеза принимается, только если средний AUC вырастает хотя бы на 0.005 и худший фолд не становится хуже. У LCNN параметров на порядки меньше, чем у XLS-R 300M, а LOSO при этом выше.

## Что отвергнуто

| Гипотеза | Средний AUC | Худший фолд | Решение |
| --- | --- | --- | --- |
| Простые признаки, этап 0 | ярлык не снимается | — | отвергнуто |
| LightGBM, этап 1 | 0.951 | 0.826 | база |
| LCNN + LFCC, этап 2 | 0.989 | 0.949, A06 | сдано, публичный 97.65 |
| Сырая CNN, этап 3 | 0.770 | 0.497, A06 | отвергнуто |
| XLS-R 300M, линейная голова, этап 4 | 0.982 | 0.896, A06 | отвергнуто |

Худший фолд в таблице — минимум AUC фолда после усреднения по трём семенам. Std и доверительный интервал считаются по этим фолдам. Модель сильна на A01–A05 и держится на A06 около 0.95. Всё, что поднимает среднее за счёт провала A06, мы не берём: закрытый тест может быть похож на незнакомый синтезатор.

Шесть фолдов A01–A06, три семени, у каждой новой гипотезы ровно 20 испытаний Optuna. Публичный тест модель не выбирает. Итог отбора записан в `outputs/decisions.json`.

Сплит по дикторам (`experiments/baseline_ablation.md`) давал валидацию около 0.99 и публичные 75.69: одни и те же синтезаторы были и в обучении, и в проверке. После этого отбор идёт только LOSO по синтезаторам.

## Как воспроизвести

### Окружение и данные

Python 3.14 и GPU с CUDA: без CUDA `stage2.submit` останавливается с ошибкой `CUDA is required`. Проверено на RTX 3050 Laptop с 4 ГБ, torch 2.13.0+cu126. Все команды запускаются из корня репозитория.

```bash
pip install -r requirements.txt
```

Аудио в репозиторий не входит. Его нужно положить так:

```
Data/train/targets.txt      протокол ASVspoof 2019 LA train
Data/train/flac/*.flac      25 380 записей
Data/public_test/*.wav      1 162 файла с именами из колонки idx в public_sample_submission.csv
```

Пути к данным и `outputs/` задаёт `af_common` относительно своего файла.

### Сданные CSV бит в бит, около 1 минуты

```bash
python -m stage2.submit --from-checkpoints
```

Скрипт считает LFCC для тестового аудио, оценивает его тремя сохранёнными весами из `outputs/stage2/final_checkpoints/` и перезаписывает `outputs/submission_seed_{0,1,2}.csv`. Результат совпадает со сданными файлами побайтно (SHA-256):

```
submission_seed_0.csv  67B3019468789DAE22F93AE072D73601430FB4EDAC126D017E23A40C285707B5
submission_seed_1.csv  713A532D285C7943FDA4C7C69D6B96AD40D019D2D3BBC7D7834B457A2282D991
submission_seed_2.csv  38CA637755E025E81BC12078D74145E133C401247A8EFC0CFEC205072B49A7A7
```

### Переобучение с нуля, около 20 минут

```bash
python -m stage2.submit
```

Скрипт декодирует обучающее аудио, строит кэш LFCC и обучает LCNN на всех размеченных записях по 10 эпох для каждого из трёх семян. Затем пишет три CSV, веса в `final_checkpoints/` и `outputs/stage2/submission.json`. Тестовое аудио только оценивается. На диске нужно около 6 ГБ под кэши: `outputs/stage2/waves_int16_resample_poly.npy` и `outputs/stage2/feat_cache/`, оба в `.gitignore`.

Эта команда перезаписывает сданные CSV и веса. Если они нужны, сохраните копию заранее.

Переобученные CSV близки к сданным, но побайтно не совпадают. Spearman между ними 0.955–0.959 для каждого семени. Между семенами внутри самой сдачи он 0.90–0.95, так что расхождение не больше обычного разброса семян. Причины две:

- Сданные веса обучены на волнах из старого кэша `Data/ablation_cache/train_waves_int16.npy`. Текущий код декодирует flac сам. На выборке из 200 записей отсчёты int16 отличаются максимум на 1 единицу округления, но после логарифма в LFCC это даёт разницу признаков до 0.04 после z-нормы. Поэтому версия кэша признаков поднята до `v2`.
- Обучение на CUDA недетерминировано даже при `cudnn.deterministic=True`. Обратный проход `AdaptiveAvgPool2d` на CUDA использует атомарные сложения, а `torch.use_deterministic_algorithms` не включён. Поэтому повтор с тем же семенем даёт близкие, но не идентичные веса.

Публичный тест у переобученной модели не измерялся.

### Повтор отбора модели (необязательно, много часов)

```bash
python -m stage1.train
python -m stage2.run_stage2
```

Эти шаги нужны только для перепроверки выбора модели, для сдачи они не требуются. `stage1.train` всегда пересчитывает LOSO и перезаписывает `outputs/stage1/metrics.json`. `stage2.run_stage2` сразу завершается, если `outputs/stage2/metrics.json` уже в статусе `complete`. Для полного повтора удалите `metrics.json`, `optuna.db` и `partial_seeds.json` в `outputs/stage2/`. Тест в этих скриптах не читается. Записанные LOSO-метрики этапа 2 посчитаны на признаках `v1`, поэтому полный повтор на `v2` даст близкие, но не идентичные числа.
